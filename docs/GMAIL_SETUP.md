# Gmail 連携（受信メール機能）設定手順

基幹システムの「受信メール」画面で、代表アドレス宛のメールを閲覧・対応管理するための設定手順です。
Google Workspace の **サービスアカウント＋ドメイン全体の委任（DWD）** で、代表アドレスのメールボックスを **読み取り専用** で参照します。

- 使う権限（スコープ）は `https://www.googleapis.com/auth/gmail.readonly` **のみ**。返信・削除・既読化・ラベル変更はできません。
- 対応ステータス（未対応／対応中／対応済み）は基幹システム内だけの情報です。Gmail の既読・ラベルとは連動しません。
- **このドキュメントには値を書かないでください。** 下記の `<...>` はすべてプレースホルダです。

所要時間の目安: 30〜45 分（Google Workspace のスーパー管理者権限が必要）

---

## 0. 全体の流れ

1. Google Cloud プロジェクトを作成する
2. Gmail API を有効化する
3. サービスアカウントを作成し、鍵（JSON）を発行する
4. Workspace 管理コンソールでドメイン全体の委任を設定する
5. Vercel に環境変数を登録して再デプロイする
6. 動作確認する
7. （必要時）鍵のローテーション／失効

あわせて、DB マイグレーション `supabase/migrations/030_inbound_emails.sql` を Supabase に適用しておく必要があります（本番適用は営業時間外を推奨）。

---

## 1. Google Cloud プロジェクトの作成

1. <https://console.cloud.google.com/> に、Workspace の管理者アカウントでログインします。
2. 画面上部のプロジェクト選択 → **新しいプロジェクト** を選びます。
3. プロジェクト名（例: `hanacho-mail`）を入力し、組織が自社の Workspace ドメインになっていることを確認して **作成** します。

> プロジェクト ID は後で使いません。リポジトリや Issue に書く必要はありません。

## 2. Gmail API の有効化

1. 作成したプロジェクトを選択した状態で、**API とサービス → ライブラリ** を開きます。
2. 「Gmail API」を検索して開き、**有効にする** を押します。

## 3. サービスアカウントの作成と鍵（JSON）の発行

1. **IAM と管理 → サービス アカウント → サービス アカウントを作成** を開きます。
2. 名前（例: `hanacho-mail-reader`）を入力して作成します。**ロール（権限）の付与は不要** です（スキップして続行）。
3. 作成したサービスアカウントを開き、**詳細** タブで次の 2 つを控えます（後で使います）。
   - **メールアドレス**（`<service-account-name>@<project-id>.iam.gserviceaccount.com` の形式）→ 環境変数 `GMAIL_SA_CLIENT_EMAIL`
   - **一意の ID（クライアント ID・数字の羅列）** → 手順 4 のドメイン全体の委任で使います
4. **鍵** タブ → **鍵を追加 → 新しい鍵を作成 → JSON** を選ぶと、鍵ファイルがダウンロードされます。
   - JSON の中の `private_key` が環境変数 `GMAIL_SA_PRIVATE_KEY` の値になります。

### 鍵ファイルの取り扱い（重要）

- 鍵ファイルは **パスワードと同じ秘密情報** です。**リポジトリ・チャット・メール・Issue・PR・スクリーンショットに絶対に貼らないでください。**
- Vercel に登録し終えたら、ダウンロードしたファイルは **安全な場所に保管するか削除** します（`ダウンロード` フォルダに残さない）。
- 組織ポリシーで「サービスアカウントキーの作成」が禁止されている場合は、Workspace/Cloud の管理者がポリシー（`iam.disableServiceAccountKeyCreation`）を一時的に許可する必要があります。

## 4. ドメイン全体の委任（Workspace 管理コンソール）

サービスアカウントが代表アドレスのメールを読めるようにする設定です。

1. <https://admin.google.com/> にスーパー管理者でログインします。
2. **セキュリティ → アクセスとデータ管理 → API の制御 → ドメイン全体の委任を管理** を開きます。
3. **新しく追加** を押し、次を入力して **承認** します。
   - **クライアント ID**: 手順 3-3 で控えたサービスアカウントの「一意の ID（数字）」
   - **OAuth スコープ**: `https://www.googleapis.com/auth/gmail.readonly`（**これ 1 つだけ**。他のスコープを足さないこと）
4. 反映には数分〜最大数時間かかることがあります（手順 6 の切り分けを参照）。

### ドメイン全体の委任の権限の強さについて（必ず読んでください）

- ドメイン全体の委任は **強力な権限** です。登録したスコープの範囲で、**ドメイン内の任意のユーザーのメールボックスを impersonate できる** 設定になります。
- そのため **スコープは `gmail.readonly` のみに限定** し、`gmail.modify` / `gmail.send` / `mail.google.com` などの広い権限を **決して登録しないでください**（第2弾の返信機能を入れる際も、改めて別途検討します）。
- このシステムは、読み取り対象を **環境変数 `GMAIL_IMPERSONATE_USER` の 1 アドレスに固定** しており、画面・リクエスト・DB の値から別のアドレスを指定する経路はありません。
- 鍵が漏れると、攻撃者は（スコープの範囲で）ドメイン内の他ユーザーのメールも読めてしまいます。漏えいが疑われたら **直ちに鍵を無効化**（手順 7）し、委任の登録も削除してください。

## 5. Vercel の環境変数

Vercel のプロジェクト → **Settings → Environment Variables** で、次を登録します。

| 変数名 | 内容 | 必須 |
|---|---|---|
| `GMAIL_SA_CLIENT_EMAIL` | サービスアカウントのメールアドレス | 必須 |
| `GMAIL_SA_PRIVATE_KEY` | サービスアカウントの秘密鍵（JSON の `private_key` の値） | 必須 |
| `GMAIL_IMPERSONATE_USER` | 読み取り対象の代表アドレス | 必須 |
| `GMAIL_INITIAL_SYNC_DAYS` | 初回／フォールバック時に遡る日数（既定 30） | 任意 |

- **すべて server-only です。`NEXT_PUBLIC_` を付けないでください**（付けるとブラウザに公開されます）。
- **対象環境**: 本番に使う環境（Production）に登録します。Preview に入れる場合も、本番と同じ代表アドレスのメールが Preview から見えることに注意してください。
- **`GMAIL_SA_PRIVATE_KEY` の改行**: JSON の `private_key` は `-----BEGIN PRIVATE KEY-----\n...\n-----END PRIVATE KEY-----\n` のように **`\n`（バックスラッシュ + n）で改行を表した 1 行** になっています。
  - **その 1 行をそのまま（ダブルクォートで囲まずに）貼り付けて構いません。** システム側でリテラルの `\n` を改行に戻します。
  - 実際の改行を含めて貼り付けても動作します。
- **登録後は再デプロイが必要** です（環境変数は新しいデプロイから有効になります）。Deployments から最新のデプロイを **Redeploy** してください。
- ローカル開発で試す場合は `.env.local` に同じ名前で設定します（`.env.local` は Git に入りません）。鍵の入った `.env.local` を共有しないでください。

> 架空データで画面を試したいだけの場合（開発のみ）は、`.env.local` に `GMAIL_FIXTURE_MODE=1` を設定します。本番環境（`NODE_ENV=production` / `VERCEL_ENV=production`）では、このフラグは無視されます。

## 6. 動作確認と、よくあるエラーの切り分け

### 動作確認

1. 管理画面にログインし、メニューの **受信メール** を開きます。
2. 画面を開くと自動で同期が始まり、代表アドレスの **直近 30 日（`GMAIL_INITIAL_SYNC_DAYS`）の受信トレイ** のメールが一覧に並びます（初回はすべて「未対応」）。
3. 代表アドレスにテストメールを送り、画面の **↻ 更新** を押すと新着が一覧に現れます。
4. 日本語の件名・本文・添付ファイル名が文字化けしないこと、添付をダウンロードして開けることを確認します。
5. Gmail 側で、基幹システムの操作によって **既読/未読・ラベルが変わっていない** ことを確認します。
6. 送信済みメール・迷惑メールが一覧に混ざっていないことを確認します。

初回で件数が多い場合は「続きがあります」と表示されます。**↻ 更新** を押すと続きを取り込みます。
お知らせ・営業メールなどは、一覧で複数選択して一括で「対応済み」にして整理できます。

### 画面にエラーが出たとき

| 表示・症状 | 主な原因と対処 |
|---|---|
| 「Gmail 連携が未設定です」 | 環境変数 3 つが未登録、または登録後に再デプロイしていない。手順 5 を確認。 |
| 「Gmail の認証に失敗しました…」 | 下記「認証エラーの切り分け」を参照。 |
| 「Gmail の利用制限に達しました」 | 短時間に更新を繰り返した可能性。数分待ってから更新。 |
| 「タイムアウト」 | 一時的な通信障害の可能性。再度更新。続く場合は Google Workspace ステータスを確認。 |
| 「他の同期が実行中です」 | 別の人が同時に更新中。少し待ってから更新（異常終了時も約 2.5 分で自動的に解除されます）。 |

エラーが出ても、取り込み済みのメールは引き続き閲覧できます。

### 認証エラーの切り分け

- **`unauthorized_client`**（Vercel のログには詳細を出していません。Google 側の Admin コンソール「ログ」で確認）
  - 手順 4 のドメイン全体の委任が未設定、またはクライアント ID が違う（メールアドレスではなく **数字の一意の ID** を登録します）。
  - 委任の反映待ち（数分〜数時間）。しばらく待って再度更新。
- **スコープ不一致**
  - 委任に登録したスコープが `https://www.googleapis.com/auth/gmail.readonly` と **完全一致** しているか（末尾のスペース・全角・別スコープの混入に注意）。
- **`invalid_grant` / 鍵の形式エラー**
  - `GMAIL_SA_PRIVATE_KEY` が途中で切れている・余計な文字が付いている。`-----BEGIN PRIVATE KEY-----` から `-----END PRIVATE KEY-----` まで全体が入っているか確認。
  - 鍵が失効・削除されている（手順 7）。
  - `GMAIL_IMPERSONATE_USER` が存在しないアドレス、または Workspace 外のアドレス。
- **403 / Gmail API has not been used…**
  - 手順 2 の Gmail API 有効化が、鍵を発行したプロジェクトと同じプロジェクトで行われているか確認。

## 7. 鍵のローテーション／失効

### 定期的な交換（推奨: 年 1 回程度）

1. サービスアカウントの **鍵** タブで **新しい鍵（JSON）を作成** します。
2. Vercel の `GMAIL_SA_PRIVATE_KEY`（必要なら `GMAIL_SA_CLIENT_EMAIL` も）を新しい値に更新し、**再デプロイ** します。
3. 手順 6 の動作確認を行い、問題なければ **古い鍵を削除** します。
4. ダウンロードした JSON ファイルは安全に保管するか削除します。

### 漏えいが疑われるとき（緊急）

1. Google Cloud の **鍵タブで該当の鍵を直ちに削除**（無効化）します。
2. Workspace 管理コンソールの **ドメイン全体の委任** から、該当クライアント ID の登録を削除します。
3. 新しい鍵を発行して手順 3〜5 をやり直します。
4. 必要に応じて、Google Workspace の監査ログで不審なアクセスがないか確認します。

### 連携を止めたいとき

Vercel の環境変数 3 つを削除して再デプロイすれば、画面は「未設定」の案内に戻ります（取り込み済みのデータは残ります）。
完全に止める場合は、ドメイン全体の委任の登録とサービスアカウント（または鍵）も削除してください。

## 補足: 保存されるデータについて

- メールの **本文（テキスト／HTML）・件名・送信者・宛先** は、基幹システムの DB（Supabase）に保存されます。閲覧できるのは admin / employee のみです（RLS で制限）。DB のバックアップ・エクスポートにもメール本文が含まれる点に留意してください。
- **添付ファイルの実体は保存しません。** ダウンロードのたびに Gmail から取得します（約 4MB を超える添付は、画面の案内に従って Gmail で開いてください）。
- 外部画像は既定でブロックされます（開封の追跡対策）。メールごとに「画像を表示」で解除できます。
